## Description

Score Prisma on the phone-quality clips. This is the Noise Canceller entry. Every number comes from real Prisma batch calls. There is no mock or fixture mode: without `GNANI_API_KEY` the runner exits non-zero with the client's missing-key message.

Systems, all through `PrismaBatch` and `batch_config` (not REST). REST has no `with_denoise`, and Prisma v2.5 rejects `keyterms`. `batch_config` already maps v2.5 hints to `bias_list` and v3.0 hints to `keyterms`. Use it.

| id | model | hints | with_denoise |
| --- | --- | --- | --- |
| `v25` | `prisma-v2.5` | none | false |
| `v25-bias` | `prisma-v2.5` | `order`, `gate`, `item`, `accident` (single words) | false |
| `v30` | `prisma-v3.0` | none | false |
| `v30-key` | `prisma-v3.0` | the same words, as keyterms | false |
| `v30-key-denoise` | `prisma-v3.0` | the same keyterms | true |

Language: `hi-IN,en-IN` on v3.0, `hi-IN` on v2.5 (v2.5 batch allows up to three codes; one is enough and avoids a surprise). Format `codemix` on v3.0 only.

Flow per the docs: `create_job` → `start_job` → poll `get_job` until `COMPLETED` or a terminal failure → `list_files` (rows under `data`) → `fetch_transcript(row["transcript_url"])` and read `full_transcript`. URLs expire after an hour; call `list_files` again if a download fails.

Cap the default grid so the free credit pool survives: `--limit 8` utterances, all five noises, SNRs `10` and `0` only, all five systems. Print the file and estimated audio-minute count before you start and refuse to run a grid over 200 files unless `--i-mean-it` is passed. Save raw transcripts per system to `benchmark/results/raw/` so a re-score never re-uploads.

Scoring:

- WER and CER from `rasta_bench.score`, reference is the manifest `reference`.
- Intent: `extract_event(hypothesis, provider="rules")` and compare to the corpus intent (join on `id`). Accuracy is correct/total.
- Aggregate mean WER, mean CER, intent accuracy, per system, and also sliced by `noise` and by `snr_db`.

Write:

- `benchmark/results/scores.json`
- `benchmark/results/scores.md` — a Markdown table, system × mean WER × mean CER × intent accuracy, plus a second small table of WER by noise for `v30` vs `v30-key-denoise`.

Commit `scores.json` and `scores.md` from the real run. Stamp the run date, the Gnani `request_id`/`job_id`s and the grid size in `scores.json` so a reader can see it is a live score.

Poll interval 10 seconds, as the docs suggest. Give up on a job after 15 minutes and record an error row rather than hanging the run.

## Input / output contract

Input: `benchmark/data/phone_manifest.jsonl` plus `benchmark/data/utterances.jsonl` for the gold intent.

`scores.json`:

```json
{
  "run_at": "2026-11-14T10:30:00+05:30",
  "job_ids": {"v30-key-denoise": "019f…"},
  "systems": [
    {"id": "v30-key-denoise", "wer": 0.0, "cer": 0.0, "intent_accuracy": 1.0, "n": 8}
  ],
  "by_noise": [
    {"system": "v30", "noise": "horn", "wer": 0.2, "n": 8}
  ]
}
```

Numbers come from Prisma transcripts, never from your head. The test rebuilds a tiny manifest (two clips, two systems) in a temp dir, fakes the batch HTTP calls with `httpx.MockTransport` inside the test, and checks the math against `wer()`.
