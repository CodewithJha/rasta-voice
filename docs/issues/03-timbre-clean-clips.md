# 03 — Clean clips from Timbre

- **Labels:** `area:benchmark`, `day:1`, `tts`
- **Owner:** Member A: benchmark & audio
- **Target day:** Day 1 (12–13 Nov 2026)
- **Depends on:** issue 01 (the jsonl must exist).

## Description

Turn each corpus line into a clean speech clip using the Timbre client that is already in the repo. This is the "before noise" stem. Later issues dirty it on purpose.

Use `TimbreTTS` from `gnani_client`. Do not edit `gnani_client/tts.py`.

Defaults, matching the client and the docs:

- model `timbre-v3.0`
- voice `Shivani`
- language `hi-en`
- container `wav`
- sample rate `16000`

This is a real Timbre run. `GNANI_API_KEY` must be set; the client raises `MissingApiKeyError` otherwise, and the script exits non-zero with that message. Wav bytes stay gitignored under `benchmark/data/audio/`. Commit the manifest after a successful run.

Cache: if a row's wav already exists and its `sha256` matches the manifest, skip the call. Re-running must not burn credits on clips you already have. `--force` regenerates. Timbre streams its WAV, so header sizes are placeholders; use `gnani_client.wav.wav_duration_seconds` for `duration_s`, not `wave.getnframes()`.

Reference text used later for WER is the corpus `text`, with no angle-bracket tags. You may pass Timbre a `spoken_text` that adds a single tag from `gnani_client.tts.AUDIO_TAGS` on at most 4 rows (a `<pauses>` on a delay, a `<whispers>` on an accident). Store both strings. Never put the tag in `reference`.

One run is a loop of REST calls (about 40, one per row). Sleep briefly if you get HTTP 429. Do not parallelise into the rate limit.

## Input / output contract

Input: `benchmark/data/utterances.jsonl`.

Output manifest, one JSON object per line:

```json
{
  "id": "u01",
  "reference": "bhaiya gate band hai, customer phone nahi utha raha, order 18",
  "spoken_text": "bhaiya gate band hai, customer phone nahi utha raha, order 18",
  "path": "benchmark/data/audio/clean/u01.wav",
  "voice": "Shivani",
  "model": "timbre-v3.0",
  "sample_rate": 16000,
  "sha256": "<hex of the wav bytes>",
  "duration_s": 4.2
}
```

Each path is a mono 16-bit WAV. `sha256` matches the file. Re-running skips rows whose wav and hash already match.

## Acceptance criteria

- [ ] `python -m rasta_bench.speak` with a real key writes one wav per corpus row and a manifest line each. Spot-check two wavs by ear: they are speech, not silence.
- [ ] Every wav starts with `RIFF`, sample rate 16000, mono, 16-bit. A test checks one file with the stdlib `wave` module.
- [ ] `reference` equals the corpus text. Tags, if any, appear only in `spoken_text`.
- [ ] Wav directory is gitignored (already in `.gitignore` as `benchmark/data/audio/`). The manifest is committed.
- [ ] `test_speak.py` needs no key: it swaps the HTTP transport inside the test (`httpx.MockTransport` returning a small WAV, or monkeypatch `TimbreTTS._http`). No flag in `speak.py` fakes Timbre.
- [ ] With `GNANI_API_KEY` unset, `python -m rasta_bench.speak` exits non-zero and prints the missing-key message.
- [ ] A second run with nothing changed makes zero Timbre calls.

## How to test

python -m rasta_bench.speak          # needs GNANI_API_KEY
